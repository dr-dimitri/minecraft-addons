# Abnahme eines Birds-Releasekandidaten

Diese Vorlage kopieren und nur beobachtete Ergebnisse eintragen. Leere Felder
und offene Punkte bedeuten keine Freigabe. Den ausgefüllten Beleg am Release
ablegen oder in einem späteren Dokumentationscommit unter `docs/releases/`.

- Produkt / Version / `birds-vX.Y.Z`-Tag:
- Vollständiger Quellcommit:
- CI-Lauf-URL und verwendete Python-/Node-Versionen:
- Datum / prüfende Person:
- Artefaktnamen und SHA-256 (einschließlich Source-ZIP):
- Windows / genaue Bedrock-Version / Hardware / Treiber:
- Welt / Seed / Grafikprofil / aktivierte Pakete mit Versionen:

Unzutreffende Prüfungen mit Begründung kennzeichnen. Beim ersten Release ist
nur der Update-von-Vorversion-Test automatisch nicht anwendbar. Bei Änderungen
am Mehrspielerverhalten zusätzlich nahe/entfernte Spieler und Abmelden prüfen.
